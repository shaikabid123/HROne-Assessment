List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

Line numbers refer to the starter exactly as supplied. "Observed" means I ran the original starter against a real
MongoDB-compatible server and saw the symptom described; "reasoned" means it follows from the code and the contract.
Every fix named below exists in the current `app/main.py` and is covered by a test in `tests/test_part_a.py`.

## Looked at and decided it is not a defect

* **`load_dotenv()` and environment precedence (L20).** The default is `override=False`, so real environment variables already win over `.env`. I kept that and made it explicit; a test copies `main.py` beside a `.env` and checks that the environment wins, `.env` fills the gaps, and each variable is handled independently. Reading `MONGO_URI` and `MONGO_DB` from the environment was already right. I kept a `localhost` fallback for local development; it contains no credentials.
* **`IST = timezone(timedelta(hours=5, minutes=30))` (L25).** Correct (UTC+05:30, no DST). Reused.
* **201 on create and punch-in.** Correct codes. The 409 paths were the problem, not the success codes.
* **`doc.pop("_id", None)` after `insert_one` (L84, L120).** It does work because `insert_one` adds `_id` to the dict. It was fragile, though, and replaced by explicit serializers that name every returned field.
* **Filter construction in `list_attendance` (L133-143).** The `emp_code`, `status` and `$gte`/`$lte` date conditions were right. `YYYY-MM-DD` strings sort chronologically as text, so string comparison on `date` is correct and index-friendly; I kept it.
* **`total = len(docs)` semantics (L146).** It counted the filtered set as required; only the way it was obtained (loading everything) was wrong (row 25).
* **Attendance `(page - 1) * page_size` (L147).** Correct, which is what exposed the off-by-one in the employee list (row 7).
* **`punch_in` returning 201 with `punch_out`, `work_hours` null, `overtime_minutes` 0, `half_day` false, `history` `[]`.** The initial values match the contract and DATA_MODEL.md. Unchanged.
* **Empty `?department=`.** The starter's `if department:` ignored an empty value. I filter whenever the parameter is present (exact match), so `?department=` returns an empty list because no employee can have an empty department (`minLength` 1). The contract does not address this; I noted it as a judgment call.

## Scope and what has not been verified

* This file covers Part A only. `punch-out`, `PATCH`, the four analytics endpoints and the explain endpoint are not implemented yet; the helpers above are written for them (rows 21-24).
* Tests ran against FerretDB 1.24 (a MongoDB wire-protocol server, reporting version 7.0.42), not a genuine `mongod`. Unique-index behaviour, concurrency, sorting, paging and the commands the app sends are real; **query plans are not**. That the list queries use `IXSCAN` with no `COLLSCAN` follows from the index definitions but has to be proven with the explain endpoint against real MongoDB.
